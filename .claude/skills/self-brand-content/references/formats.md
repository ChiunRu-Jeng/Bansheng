# formats.md：三平台格式規範

三版共用同一份敘事骨架（見 SKILL.md 第 2 步），但**敘事策略、結構、長度必須互異**。共同硬規則：

- 首行必須是鉤子（提問、反直覺結論、或衝擊數字），不得是陳述句
- 內文至少一個具體數字
- 四元素齊備：鉤子 → 案例敘事 → 能力證明 → 軟 CTA

---

## 版本 A｜LinkedIn 長文版

**受眾心態**：專業場合，決策者與同儕在看。願意讀長文，但要有結構感。
**敘事策略**：完整的問題→過程→結果弧線，重點放「怎麼想」——展現判斷力而非執行力。

- 長度：600–1000 字（繁體中文）
- 結構：
  1. 鉤子（1–2 行，之後空一行製造「看更多」斷點）
  2. 情境：客戶背景（去識別化）＋原本流程的痛
  3. 障礙：真實卡點，含技術與人的因素
  4. 解法：關鍵決策與取捨，**寫出為什麼不選另一條路**
  5. 數字：前後對照的成效
  6. 能力證明：從這個案子提煉的一條可遷移方法或判斷準則
  7. 軟 CTA：開放式提問或「私訊聊聊」
- 排版：每段 1–3 行、段落間空行；可用「①②③」或破折號列點；**不用** emoji 開頭列點
- Hashtag：文末 3–5 個（例：#AI導入 #數位轉型 #中小企業），不塞內文

## 版本 B｜FB 中文版

**受眾心態**：滑動速度快、氛圍輕鬆，朋友與在地企業主居多。長篇結構文會被滑掉。
**敘事策略**：說故事口吻，像跟朋友講一件工作上的事。重點放「現場感」——對話、場景、情緒轉折。

- 長度：200–400 字（繁體中文）
- 結構：
  1. 鉤子（口語化的一句，可以是客戶說過的話）
  2. 場景：一個具體畫面或對話切入，不鋪背景
  3. 轉折：卡點＋解法壓縮成 2–3 句，數字放在轉折處
  4. 收尾：一句能力證明（輕描淡寫）＋軟 CTA（提問式，邀請留言）
- 排版：口語、短段落，可少量 emoji（1–3 個，放段落開頭或結尾，不洗版）
- 不放 hashtag 或最多 1–2 個；不用列點符號——FB 版是「講話」不是「簡報」

## 版本 C｜短影音腳本版

**受眾心態**：3 秒內決定滑不滑走。聽覺為主、視覺輔助。
**敘事策略**：單一衝突點。整支只講「一個卡點怎麼被解掉」，其他細節全砍。

- 長度：30–60 秒口播，逐字稿約 150–220 字
- 結構（分鏡表格式，含秒數）：

  | 秒數 | 口播（逐字） | 畫面/字卡提示 |
  |------|------------|--------------|
  | 0–3 | 鉤子（問句或數字開場） | 大字卡打出鉤子 |
  | 3–15 | 情境＋卡點（一句話講完客戶是誰，直奔問題） | B-roll 或示意畫面 |
  | 15–40 | 解法＋數字（數字要口播唸出來，同步上字卡） | 前後對照字卡 |
  | 40–55 | 能力證明（一句） | 回到人臉 |
  | 55–60 | 軟 CTA（口語、一句） | 字卡：追蹤/私訊 |

- 口播規則：全部用「講的中文」寫，不寫書面語；一句不超過 20 字，唸得順才算過
- 每個數字都要配字卡；鉤子與成效數字是兩個必上的字卡
- 結尾 CTA 不喊「立刻聯絡我」，用「你們公司也有這種流程的話，留言跟我說」這類邀請句

## 三版互異性檢查

產出後快速比對，若任兩版出現以下情況即重寫其一：

- 首行鉤子句式相同（例：兩版都用數字開場 → 換一版改成提問或反直覺結論）
- 段落結構相同（LinkedIn 是完整弧線、FB 是場景切入、短影音是單一衝突，不可互換）
- 可以整段複製貼上到另一版而毫無違和 → 代表沒有為平台改寫
