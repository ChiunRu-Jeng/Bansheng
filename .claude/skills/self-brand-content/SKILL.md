# self-brand-content：實作案例 → 三平台品牌貼文

## 定位

Ru 的個人品牌定位是「AI 導入顧問」：不賣工具、賣落地。每篇內容的目的是讓目標受眾看完後相信「這個人做得出來、講得出所以然」，並在有需求時想到 Ru。這是獲客流程第②階段（每週曝光）的產出工具，不是成交工具——貼文只負責建立信任與記憶點，CTA 一律放軟。

## 輸入（開始前必須確認齊全）

1. **案例素材**，四要素缺一不可：
   - 做了什麼（專案一句話）
   - 遇到什麼（卡點、阻力、意外）
   - 怎麼解（方法、取捨、為什麼這樣選）
   - 成效數字（時間、金額、次數、比例——至少一個可寫進貼文的具體數字）
2. **本季定錨文件**：本季主打案型與目標受眾。先找 `docs/agent-os/` 下的定錨文件；找不到就問使用者本季案型與受眾是什麼，不要自己猜。

任一要素缺漏 → 先向使用者補問，不要用空泛描述硬寫。

## 工作流程

### 第 1 步：機密過濾（寫任何字之前先做）

逐項檢查素材，以下內容**絕對不得出現在任何一版**：

- 客戶價格底線、報價、合約金額、折扣條件
- 未取得授權的客戶名稱、品牌名、可反推出客戶的獨特細節
- 客戶內部系統名稱、內部人名、未公開的營運數字

替代寫法：用「一家約 30 人的製造業貿易公司」這類**產業＋規模**描述取代客戶名；用「六位數的年度人力成本」這類量級描述取代精確金額。成效數字（節省時間、錯誤率下降等）屬於 Ru 的交付成果，可寫，但不得精確到能反推客戶身分。

### 第 2 步：萃取敘事骨架

從素材整理出一份骨架，三版共用：

| 元素 | 內容 |
|------|------|
| 鉤子 | 一句讓目標受眾停下來的話——痛點提問、反直覺結論、或具衝擊力的數字。**不能是平鋪陳述句** |
| 情境 | 客戶是誰（去識別化）、原本的做法、為什麼撐不下去 |
| 障礙 | 導入過程真實的卡點（技術的、人的、流程的） |
| 解法 | 怎麼解、關鍵取捨、為什麼不選另一條路 |
| 數字 | 至少一個具體成效數字，放在敘事的轉折點 |
| 能力證明 | 這個案子證明了 Ru 的什麼判斷力或方法論（一句話，不吹噓） |
| 軟 CTA | 邀請對話而非推銷：「你們也卡在類似的地方嗎？」「想知道評估方法可以私訊聊聊」 |

### 第 3 步：產出三版

依 [references/formats.md](references/formats.md) 的格式規範，把同一份骨架寫成三版。三版**格式必須互異**——不是同一篇文換長度，而是換敘事策略（詳見 formats.md 各平台的敘事策略）。

### 第 4 步：語調檢查

逐版比對 [references/voice.md](references/voice.md)：直接、有數字、不吹噓。發現違規字眼（「頂尖」「完美」「顛覆」之類）就改寫。

### 第 5 步：自我驗收（輸出前逐項打勾）

- [ ] 三版皆完整產出，且格式互異（結構、長度、敘事策略各不相同）
- [ ] 每一版的**首行是鉤子**，不是陳述句（自測：把首行單獨唸出來，若像報告開頭就重寫）
- [ ] 每一版內文至少一個具體數字
- [ ] 全文零機密：無價格底線、無未授權客戶名、無可反推客戶身分的細節
- [ ] 每一版都含：鉤子、案例敘事、能力證明、軟 CTA 四元素

任何一項不過 → 修完再輸出，不輸出半成品。

## 輸出格式

以三個明確分隔的區塊輸出，各版開頭標示平台與建議用途：

```
## 版本 A｜LinkedIn 長文版
（內文）

## 版本 B｜FB 中文版
（內文）

## 版本 C｜短影音腳本版
（分鏡表）
```

最後附一行機密檢查聲明：列出素材中被過濾掉的項目（若有），讓 Ru 發文前能再確認一次。
